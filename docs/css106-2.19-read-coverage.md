# CSS106 SwOS 2.19 protocol coverage

This document records the local web-interface surface implemented for
RB260GS (`CSS106-5G-1S`) running SwOS `2.19`, build `0x6a181cd5`.

The independently inspected `/index.html` was 37,733 bytes with SHA-256 digest
`6f631be833b4ff2d5445652422d0087448038e506ea3081fcf9a558c7aed1579`.
Its embedded JavaScript supplies endpoint names, field mappings, enum order,
bit assignments, counter high words, and display scaling. The implementation
uses only bounded GET requests and a non-evaluating parser.

## Wire rules

| Representation | Decoding |
| --- | --- |
| Per-port array | Six entries ordered Ethernet 1-5, then SFP |
| Port bitmask | Bit 0 is port 1 through bit 5 for port 6 |
| Wide counter | `low + (high << 32)` with unsigned 32-bit words |
| Text | Hex-encoded UTF-8, NUL-terminated when applicable |
| IPv4 | Unsigned 32-bit little-endian value; zero is unspecified |
| MAC | Twelve hexadecimal digits; zero is unspecified where permitted |
| Boolean | Integer `0` or `1` |
| Table | Ordered array of objects |

All arrays, masks, integer ranges, documented ACL/VLAN table limits, UTF-8 text,
and address forms are validated before a public model is created. Other tables
remain bounded by the 1 MiB response limit.

## System and management

| Raw fields | Normalized data |
| --- | --- |
| `brd`, `ver`, `bld` | Exact product, firmware, and build identity |
| `id`, `sid`, `upt` | Device name, serial, uptime in seconds (`upt / 100`) |
| `ip`, `sip`, `iptp` | Current/static address and address mode |
| `mac`, `amac` | Current and optional administrative MAC |
| `alla`, `allm`, `allp`, `avln` | Management source network, ports, and VLAN |
| `wdt` | Watchdog configuration |
| `ivl` | Global independent VLAN lookup |
| `igmp`, `igmq`, `igfl`, `igve` | IGMP snooping, configured/effective querier, fast-leave ports, version |
| `pdsc` | Discovery-protocol ports |
| `volt`, `temp`, `lcbl` | Model-gated voltage, signed temperature, PoE-in long-cable state |

RB260GS exposes zero-valued `volt`, `temp`, and `lcbl` fields but its UI gates
them to RB260GSP. They therefore normalize as unavailable instead of false `0 V`
or `0 C` readings. `dsc` is superseded by `pdsc`; `upgr` is internal and unused
by this firmware's UI, so neither is assigned speculative public semantics.

System configuration writes serialize the complete UI-owned object in exact
order: `iptp`, `sip`, `amac`, `id`, `alla`, `allm`, `allp`, `avln`, `ivl`,
`igmp`, `igmq`, `igfl`, `igve`, `pdsc`. Read-only `ip`, `mac`, `sid`, `brd`,
version/build/runtime/health fields, watchdog, discovery legacy state, upgrade,
and bridge fields are excluded. A caller supplies a sparse typed update plus the
full initial `SystemInfo`; the adapter compares all normalized writable fields
with a fresh read, posts one complete preserved body, and verifies that complete
object through readback.

Address acquisition is `0` DHCP with fallback, `1` static, `2` DHCP only.
IPv4 is little-endian, optional admin MAC is twelve lowercase hex digits with
zero for unset, text is hex, `allm` is 0-32, `avln` is 0-4095, masks are six
bits, booleans are 0/1, and IGMP v2/v3 is 0/1. Every number uses the UI's minimum
even-width lowercase hexadecimal format, including `0x00` for zero. The UI's
`Kb` behavior is retained: disabling snooping forces the desired querier value
to false, including otherwise unrelated complete system writes.

Port 6 must remain unchanged in all masks and must be present in the management
allowed-port result. Admin-MAC override changes in either direction reboot the
device and use same-URL reconnect. Management VLAN, address-mode, and active
static-IP changes also close the POST transport and poll a selected URL for exact
identity plus complete writable-state readback. Reconnect polling allows about
one minute for reboot or address transition. Static mode derives that URL by
replacing the current URL host with the desired static address. DHCP target
changes require an explicit bare same-scheme/same-effective-port URL unless an
active DHCP lease is provably already the current endpoint. A DHCP-fallback
static address equal to the operational address is active: changing it derives
and reconnects to the new static target. Explicit readback URLs cannot override
a deterministic static target. Dormant static IP staging is allowed only while
fallback has an active DHCP lease, not in DHCP-only mode.
Static management targets reject unspecified, loopback, multicast, reserved,
and limited-broadcast IPv4 values before transport creation. Ordinary private
and IPv4 link-local unicast addresses remain accepted.

Admin MAC, allow-from, allowed-port, management VLAN, and active address changes
are intentionally available as explicit lockout operations. Successful results
carry a `management_lockout_risk` warning with before/after values. Reconnect
verification retries through address/ARP transition and updates the adapter
connection only after success. Failure issues no second write, leaves the old
connection object in place, and raises an uncertain-state error that can require
a manual factory reset. Identity verification also preserves the original
serial number and physical MAC. Definitive POST rejection is propagated without
polling; polling is reserved for ambiguous transport loss after the send.

Administrator password rotation accepts an ASCII new password of at most 15
characters and a current password of at most 15 JavaScript UTF-16 code units,
including empty values. The request body is `{pwd:'<lowercase hex>'}`. The
32-entry plaintext buffer is current-password UTF-16 code units, NUL,
new-password ASCII code units, then zero padding. RC4 uses `*` when the current
password is empty; otherwise its UTF-16 code units are repeated to at least 16
entries and truncated to 16. The key schedule applies JavaScript's `& 255`
bitwise behavior. The first 64 keystream bytes are XORed into the buffer at
indices `t & 31`.

Hex rendering uses a minimum width of two without truncating values above
`0xff`, exactly like the UI's `toString(16).padStart(2, "0")`. ASCII current
passwords therefore produce the usual 64 digits, while higher UTF-16 code units
can produce a longer result. Deterministic tests include BMP and surrogate-pair
current-password vectors independently evaluated against the UI JavaScript.

The POST uses the current connection credentials. Verification creates a new
transport with otherwise identical connection settings and reads `/sys.b` using
only the new password, requiring exact identity. The adapter replaces its saved
connection only after that verification succeeds, so subsequent operations on
the same facade use the new credentials. There is no old-credential readback
and no same-password no-op optimization. A successful result is always
`changed=true` and includes an `administrator_credentials_changed` warning.

## Ports and RSTP

| Endpoint/raw fields | Normalized data |
| --- | --- |
| `link.b`: `nm`, `en` | Name and configured enabled state |
| `link.b`: `lnk`, `spd`, `dpx` | Link state and operational speed/duplex |
| `link.b`: `an`, `spdc`, `dpxc`, `fct` | Autonegotiation, forced speed/duplex, flow control |
| `link.b`: `poe`, `prio`, `poes`, `curr`, `pwr` | Model-gated PoE configuration/status/readings |
| `rstp.b`: `ena`, `rstp`, `role`, `p2p`, `edge` | Per-port RSTP configuration, independent point-to-point/edge flags, and normalized role/type |
| `rstp.b`: `cst`, `rpc`, `lrn`, `fwd` | Configured cost, root cost, and operational state |
| `sys.b`: `prio`, `cost`, `frmc`, `rpr`, `rmac` | Bridge priority/mode and selected root |

Operational speed and duplex are unavailable when link is down. PoE is not
reported as a valid zero measurement on RB260GS; it remains model-gated for the
unsupported RB260GSP profile.

`/link.b` writes post the complete writable state in the order `en`, `nm`, `an`,
`spdc`, `dpxc`, `fct`; operational `lnk`, `spd`, and `dpx` are never posted.
Configuration and name writes are restricted to Ethernet ports 1-5 so the
port-6 SFP management path remains unchanged. Auto negotiation changes only
`an`; forced negotiation clears `an` and sets `spdc` plus `dpxc`. Every write
uses an exact identity check, no-op detection, one POST, and complete writable
state read-back. Active ports cannot be disabled or have negotiation changed.

Per-port RSTP enable writes use typed desired state and post the complete `ena`
group. They preserve bit 5 (port 6) exactly. Bridge serialization posts the
complete `prio`, `cost`, `frmc` group, but `rstp_bridge_write` is not advertised
pending hardware validation. Both paths recheck exact identity, require fresh
configuration to match the caller's expected baseline, skip no-ops, and verify
complete-group readback. The stale-plan baseline retains `p2p` and `edge` as
independent flags; their normalized edge-first display type is not used as the
write precondition.

`get_port_statistics()` always returns every group. CLI flags select only the
presentation: `--rates`, `--traffic`, `--sizes`, `--errors`, and `--full`.

| Group | Raw fields | Conversion |
| --- | --- | --- |
| Rates | `rrb`, `trb` | Raw value divided by `0.08`, bits/s |
| Packet rates | `rrp`, `trp` | Raw value divided by `0.64`, packets/s |
| Bytes | `rb`/`rbh`, `tb`/`tbh` | 64-bit low/high pairs |
| Total packets/errors | `rtp`, `ttp`, `rte`, `tte` | Unsigned 32-bit counters |
| Traffic kinds | `rup`/`ruph`, `tup`/`tuph`, `rbp`/`rbph`, `tbp`/`tbph`, `rmp`/`rmph`, `tmp`/`tmph` | 64-bit unicast, broadcast, multicast counters |
| Size buckets | `r64`..`rmax`, `t64`..`tmax` | 64, 65-127, 128-255, 256-511, 512-1023, 1024-1518, 1519-max |

| Tx detail | `tpp`, `tur`, `ttl`, `tcl`, `tec`, `tmc`, `tsc`, `ted`, `tdf`, `tlc` | Pause, underrun, too-long, collision/deferred variants |

interval is not assumed independently.

## SFP

| Raw fields | Normalized data |
| --- | --- |
| `vnd`, `pnr`, `rev`, `ser`, `dat`, `typ` | Vendor, part, revision, serial, date, media type |
| `tmp` | Signed low 16-bit Celsius; `-128` is unavailable |
| `vcc` | Volts (`raw / 1000`) |
| `tbs` | Tx bias in mA |
| `tpw`, `rpw` | `floor(1000 * 10 * log10(raw / 10000)) / 1000` dBm |

Zero optical power is unavailable because logarithmic conversion is undefined.
`wln` is returned but unused by the exact UI and its unit is unresolved, so it
is intentionally not exposed with an invented meaning.

## Forwarding and VLAN

| Raw fields | Normalized data |
| --- | --- |
| `fp1` through `fp6` | Allowed destination ports for each source port |
| `lck`, `lckf` | Port lock and lock-on-first flags |
| `imr`, `omr`, `mrto` | Ingress/egress mirror sources and single target |
| `or` | Egress limit in bits/s; zero is unlimited |
| `vlan`, `vlni`, `dvid`, `fvid`, `vlnh` | Per-port VLAN mode, receive policy, default/forced ID, egress behavior |
| VLAN rows: `vid`, `ivl`, `igmp`, `prt` | VLAN ID, learning/snooping flags, per-port membership behavior |

`ir`, `srt`, and `suni` are shared-schema fields not rendered by the RB260GS
2.19 UI. The CSS106 manual assigns ingress rate limiting to ACL rules. These
fields remain intentionally unsupported rather than receiving guessed labels.

Forwarding writes always post the complete ordered group `fp1` through `fp6`,
`lck`, `lckf`, `imr`, `omr`, `mrto`, and `or`. The advertised
`forwarding_port_policy_write` capability can change only lock, lock-on-first,
or egress rate on ports 1-5. It preserves every matrix and mirror value plus all
other rates. `fp6` and each port-6 destination relationship are immutable, and
port 6 is rejected as a mirror source or target. Matrix and mirroring encoders
are implemented behind separate unadvertised capabilities pending hardware
validation. Every forwarding mutation requires a fresh baseline match, skips
no-ops, and verifies complete-group readback.

Per-port VLAN writes post the complete ordered group `vlan`, `vlni`, `dvid`,
`fvid`, and `vlnh`. The advertised `vlan_port_policy_write` capability targets
only ports 1-5 and preserves all five values for port 6 exactly. Mutations
require a caller baseline, reject stale fresh reads, skip exact no-ops, and
verify complete-group readback.

Whole `/vlan.b` replacement emits complete ordered `vid`, `ivl`, `igmp`, `prt`
rows after exact identity and baseline checks. Desired rows must declare ports
1-6 in order and preserve port 6's membership mode for every VLAN ID, treating
an absent row as not-member. Full-table readback is mandatory. The independent
`vlan_table_write` capability remains disabled pending hardware validation.
Write-state parsing retains wire row order for comparison, while public reads
remain sorted by VLAN ID.

## IGMP groups

Dynamic `/!igmp.b` rows decode `addr`, `vlan`, and `prts` into multicast IPv4,
VLAN ID, and member ports. The endpoint refresh behavior and empty table are
hardware-validated; populated rows use a synthetic fixture.

## ACL rules

Up to 32 ordered rules are decoded. Match fields cover ingress ports, source and
destination MAC/masks, EtherType, VLAN tag/ID/priority, source and destination
IPv4/prefix/port ranges, IP protocol, and DSCP. Action fields cover redirect,
drop, mirror, ingress rate, VLAN ID rewrite, and priority rewrite.

Drop is the documented wire representation `snde=1` with `snd=0`. Wildcard
sentinels are normalized where the wire roundtrip requires it: zero source or
destination MAC/IP, VLAN priority `8`, DSCP `64`, set-priority `8`, zero rate,
and zero set-VLAN ID. Other numeric match values remain visible without
speculative wildcard interpretation.

Static-host and ACL replacement code handles complete ordered tables. The
adapter rechecks exact device identity, requires its fresh table to equal the
caller's expected baseline, skips exact no-ops, emits one ordered POST, and
verifies the complete readback. Static-host rows use `prt`,
`adr`, `vid`, `drp`, `mir`. ACL rows use `frm`, `smac`, `smsk`, `dmac`, `dmsk`,
`et`, `vlan`, `vidl`, `vidh`, `prio`, `sip`, `sipm`, `sptl`, `spth`, `dip`,
`dipm`, `dptl`, `dpth`, `prot`, `dscp`, `snde`, `snd`, `mirr`, `rate`, `svid`,
`spri`. Static targets and ACL ingress exclude management port 6. ACL write
serialization and safety are fixture-tested, but `acl_write` is not advertised
because no unequivocally harmless link-down port-5 rule was identified and
restored on hardware.

## Excluded actions

Read parity covers local information represented by the web UI. Reboot,
firmware upgrade checks/uploads, backup downloads, and restore remain outside
this milestone. Guarded device-name, port-name, and SNMP contact/location writes
were added after this audit. Every write rechecks exact identity, reads before
writing, skips no-op POSTs, and verifies the full relevant writable state.
Device-name writes use the same complete preserved system body. SNMP metadata
writes preserve raw `en` and `com` values in complete ordered
`{en,com,ci,loc}` bodies.
