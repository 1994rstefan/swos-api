# CSS106 SwOS 2.19 UI function matrix

## Scope and evidence

This is an independent audit of the local web UI served by an RB260GS
(`CSS106-5G-1S`) running SwOS `2.19`, build `0x6a181cd5`. Existing protocol and
coverage documents were not treated as evidence. The evidence was fetched again
from the device on 2026-09-18 and inspected without evaluating its JavaScript.

| Artifact property | Verified value |
| --- | --- |
| Request | Authenticated, bounded `GET /index.html`; no hardware POST was made |
| Response | `HTTP/1.0 200 OK`, `Content-Type: text/html`, `Content-Encoding: gzip` |
| Compressed body | 13,656 bytes; SHA-256 `4e016aa0dcc4376cd5b2bbd74fb33e4d8196f58d7590649c86b63de8930c5040` |
| Decompressed UI | 37,733 bytes; 37,723 JavaScript/DOM UTF-16 code units |
| Exact UI SHA-256 | `6f631be833b4ff2d5445652422d0087448038e506ea3081fcf9a558c7aed1579` |
| Device identity | `/sys.b`: `CSS106-5G-1S`, SwOS `2.19`, build `0x6a181cd5` |
| Raw evidence | Ignored `integration-artifacts/css106-2.19-index.html` and `.decoded.html`; never source-controlled |
| Machine-readable result | `docs/css106-2.19-ui-manifest.json` |

The embedded source names its generic controls and serializers. The principal
evidence functions are `ja` (strict numeric parser), `ka` (minimum-width hex),
`la`/`ma` (password transform), `wa`/`H` (bit extraction and checkbox packing),
`I` (enum), `J` (unsigned number and SI suffixes), `ya` (signed number), `K`
(MAC), `L` (IPv4), `M`/`za` (hex text), `Ga`/`Ha` (object/table wire
serialization), `R` (POST), `eb` (GET), `Y` (endpoint and read-only setup),
`Gb` (all page/control definitions), and `Hb`/`Ib`/`Kb` (dependent-control
logic). The manifest records every definition rather than relying on renamed
public fields.

The committed manifest is a frozen oracle derived from the identified UI
artifact and reviewed evidence. CI validates that oracle against public models,
serializers, command/module inventories, field constraints, and recorded hashes;
it intentionally does not read or claim a direct comparison with the ignored
live `index.html` artifact.

## Control grammar

| Source control | HTML/type | Read/display behavior | Input and exact wire behavior |
| --- | --- | --- | --- |
| `G` | read-only `span` | Scalars, arrays, bit fields, enum labels, units and scaling; absent/empty becomes NBSP | Never contributes to POST |
| `H` | checkbox or radio | One bit per control; port 1 is bit 0 through port 6 bit 5 | Checkbox emits packed integer; `za:1` makes `mrto` a same-name radio group |
| `I` | `select` | Option index is the wire value | `selectedIndex`; `-1` is coerced to 0 when saved |
| `J` | text numeric | Unsigned; optional scaling, SI display, base, width, unit, low/high combination | Canonical digits after leading zeros; empty is `l` or 0; optional `k/m/g` means decimal 1000 powers; rounded before serialization |
| `ya` | text signed | Low 16-bit signed by default; optional 8/32-bit mode | Decimal signed input, optional float mode, scaling, rounded, then two's-complement wire value |
| `K` | text MAC | Twelve wire digits display as six colon-separated octets; zero may display empty depending on `V` | Six greedy one- or two-digit hex groups; spaces and colons may separate groups, separators are optional between two-digit groups, and one trailing colon is accepted; normalized to 12 lowercase digits |
| `L` | text IPv4 | Little-endian 32-bit value; zero displays empty | Empty to 0; four decimal octets, plus `a.b` -> `a.0.0.b` and `a.b.c` -> `a.b.0.c`; each octet 0..255 |
| `M` | text | Hex decoded until NUL | At most `ba || 16` JavaScript UTF-16 units; each code unit encoded into UTF-8-like bytes. Surrogate pairs become CESU-8, not scalar UTF-8 |
| `N` | composite text | Joins nested controls with `.`, `/`, `:`, or `-` | Splits and delegates to each nested validator; omitted trailing pieces receive empty/default input |
| `Aa` | adjacent controls | Combines operational and configured link values | Saves only writable nested controls |

### Numeric details

`ja` strips leading zeros, parses in the declared radix, and requires the
canonical parsed value to equal the remaining digits case-insensitively. Signs,
whitespace, decimals, exponent notation, and `0x` prefixes are rejected by
unsigned controls. `J` checks `min`/`max` only for non-empty input; an empty
field writes the default/sentinel without those checks. `Ga` serializes numbers
through JavaScript bitwise operators, so values are effectively reduced to the
low unsigned 32 bits even where the UI declares no maximum.

Read-only rate display uses SI suffixes and decimal powers. Writable `or` and
ACL `rate` accept a suffix and store the resulting integer directly in bits per
second. Statistics instead divide the raw sample by `0.08` for bit rates and by
`0.64` for packet rates. Read-only SI display uses a strict `>` threshold,
rounds scaled `k/M/G` values to two decimals, and rounds unscaled values to a
whole number. Ordinary unscaled numeric display uses Latvian locale grouping.

### Text details

UI limits are UTF-16 code-unit counts: 16 for identity/port/SFP text and 64 for
SNMP text. The UI does not restrict controls, NUL, non-ASCII BMP characters,
unpaired surrogates, or supplementary characters. ASCII maps normally; a BMP
unit maps to normal UTF-8 byte forms; each half of a surrogate pair is encoded
separately as three bytes. The decoder stops at the first zero byte and rebuilds
JavaScript code units. The public safe reader truncates raw bytes at that NUL,
combines valid CESU-8 high/low surrogate pairs into a Unicode scalar, and rejects
unpaired surrogates and controls. This is observably different from ordinary
Unicode-scalar UTF-8 while avoiding unsafe text in public output.

### Common wire rules

| Representation | Exact meaning |
| --- | --- |
| Port mask | Six bits; bit `n-1` represents port `n`; no UI-wide port-6 protection |
| Per-port array | Exactly six values ordered Ethernet 1-5, SFP 6 |
| Boolean control | Checkbox state serializes as integer `0` or `1` |
| Number | Lowercase `0x` hexadecimal, minimum even digit count; numbers beyond 32 bits wrap through JS bitwise coercion |
| Wide counter | `low + high * 2^32` |
| Table | Ordered array of ordered objects; cut/insert/append/clear operate client-side, Apply All replaces the table |
| Text | Lowercase hex byte string, decoded only until NUL |
| IPv4 | Little-endian unsigned 32-bit integer; zero is blank/wildcard/unset according to the field |
| MAC | Twelve lowercase hex digits; zero meaning is field-specific |

### Static hosts

| Field ID | Label/type | Exact UI rule | Public mapping |
| --- | --- | --- | --- |
| `prt` | Port/six checkboxes | All six checked by default; empty mask allowed | `port_numbers`; public writes allow only ports 1-5 |

### ACL

Apply All posts up to 32 ordered objects with this field order among fields that
are present:
`frm,smac,smsk,dmac,dmsk,et,vlan,vidl,vidh,prio,sip,sipm,sptl,spth,dip,dipm,dptl,dpth,prot,dscp,snde,snd,mirr,rate,svid,spri`.

## Model-specific omissions

`Z` returns controls only when the normalized board name is `CSS106P`. For this
RB260GS, the UI omits:

| Endpoint/fields | CSS106P controls | RB260GS implementation behavior |
| --- | --- | --- |
| `/link.b`: `poe,prio,poes,curr,pwr` | PoE mode, priority, status, current, power on physical ports 2-5 | Wire arrays exist; public PoE fields remain `None` for every RB260GS port |
| `/sys.b`: `lcbl,volt,temp` | Port1 PoE-in long cable, health voltage and signed temperature | Wire scalars exist as zero; `SystemHealth` contains unavailable (`None`) values |

This omission is distinct from live wire fields that have no control definition:
`/sys.b` `upt,ip,wdt,dsc,upgr`; `/sfp.b` `wln`; `/fwd.b` `ir,srt,suni`; and
`/rstp.b` `cst`. Public reads deliberately expose `upt`, `ip`, `wdt`, and `cst`;
the other six remain unassigned.

### Password transform

No secret or transformed secret was captured. The UI checks that new and confirm
match, old password length is at most 15 JavaScript UTF-16 code units, new
password length is at most 15 code units, and every new code unit is U+0000 to
U+007F. Empty old and new passwords are valid.

The 32-unit plaintext buffer is old-password UTF-16 units, one NUL, new-password
ASCII units, then zero padding. The RC4 key is `*` for an empty old password;
otherwise old UTF-16 units are repeated to at least 16 and truncated to 16. KSA
uses JavaScript `& 255`. Sixty-four PRGA bytes are XORed into
`buffer[index & 31]`, so each buffer position is transformed twice. Rendering
uses `unit.toString(16).padStart(2,"0")`, lowercase, with no truncation; old
units above `0xff` can therefore produce more than 64 output digits. The public
encoder at `packages/devices/css106/src/swos_device_css106/protocol.py:408`
matches this transform and its UTF-16/new-ASCII limits.

## Findings

The audit distinguishes UI acceptance from proven device acceptance. Because no
POST was permitted, values accepted by client-side validation but not covered by
existing destructive tests remain “UI-accepted/device-unverified,” not claimed
device support.

Every finding has a resolution classification in the machine-readable manifest.
“Safety guard” means a deliberately narrower public contract, not an unresolved
parity claim; “explicitly excluded” covers destructive operational actions that
remain outside this milestone.

### High

1. **D01 partially resolved; intentional safety guard.** Public writes now
   accept printable Unicode by UTF-16-unit length, emit CESU-8 for supplementary
   characters, and combine valid CESU-8 surrogate pairs on reads. Controls, NUL,
   and unpaired surrogates accepted by the UI remain intentionally rejected.
2. **D02 resolved: complete SNMP writes.** Enabled, secret community, contact,
   and location are exposed through core, CLI, and Ansible while preserving
   omitted raw fields. Write inputs and CLI/Ansible write results redact the
   community; established normalized reads intentionally expose it.
3. **D03 resolved: RSTP dependencies.** Public and adapter validation use fresh
   effective state to reject changed `ena`, `prio`, or `cost` values while
   `frmc` is enabled. `frmc` itself remains changeable.
4. **D04: eight operational capabilities are absent.** Backup save/restore,
   reset configuration, reboot, reset counters, automatic/manual upgrade, and
   logout have no core/API/CLI/Ansible operation. The password action alone is
   implemented. References: public protocol in `api.py:41-359`, CLI command list
   in `app.py:317-1991`, and manifest `actions`.

### Medium

1. **D05: port 6 is an intentional safety subset, not UI parity.** The UI exposes
   port 6 throughout link, forwarding, RSTP, VLAN, hosts, ACL ingress, and system
   masks. Public operations reject or preserve it. References:
   `protocol.py:1549-1571`, `adapter.py:1159-1182`, CLI bounds such as
   `app.py:765`, and Ansible module choices. This may be desirable policy, but it
   must not be described as full write parity.
2. **D06: static management IP rejects UI-accepted values.** The UI `L` control
   accepts every 32-bit address, including zero via blank. Public non-unset input
   rejects unspecified, loopback, multicast, reserved, and broadcast addresses.
   Reference: `models.py:187-201`.
3. **D07: public ACL range ordering is narrower.** UI validates the low/high VLAN
   and transport endpoints separately and accepts low > high. The model rejects
   all three reversed ranges. Reference: `models.py:594-603`.
4. **D08: clearing a mirror target is a non-UI public option.** `mrto` is a radio
   group without a clear choice after selection; public models and CLI expose
   `none`/`--no-target`. References: `models.py:461-479` and
   `app.py:1155-1168`.
5. **D09 resolved: public desired booleans are strict.** Integers and strings are
   rejected at reusable write-model boundaries; CLI and Ansible convert their
   external representations explicitly.
6. **D10: bridge-priority validation is narrower than the UI.** UI accepts any
   non-negative canonical hex input and then applies 32-bit serialization.
   Public input requires 0..0xf000 and a multiple of 0x1000. Reference:
   `models.py:715-731` and CLI duplication at `app.py:1633-1656`. Device behavior
   for other UI values is not independently write-verified.
7. **D11: active-link safety is not a UI rule.** Public code refuses disable or
   negotiation changes on a link-up port; the UI permits Apply All. Reference:
   `adapter.py:346-353` and `adapter.py:388-395`.
8. **D16 resolved: public desired integers are strict.** Booleans and numeric
   strings are rejected for integer fields; documented string-to-enum behavior
   remains supported.
9. **D17 resolved: documentation now distinguishes parity from policy.** Text
   encoding, complete SNMP writes, strict input types, safety-bounded subsets,
   and non-UI wire fields are documented explicitly.
10. **D22 partially resolved: optional ACL MACs now match UI wire shape.** `None`
    omits `smac`/`dmac`. Blank static-host MAC remains intentionally
    unrepresentable because it is a UI validation hole, not a valid public row.

### Low

1. **D12: public MAC/IP syntax is narrower.** UI accepts one-digit MAC octets,
   ignored spaces, and two/three-component IPv4 shorthand. Public models require
   six two-digit colon octets and canonical Python `IPv4Address` syntax.
   References: `models.py:95-107`, `models.py:210-222`, and ACL validators at
   `models.py:537-592`.
2. **D13: public reads include non-UI wire semantics.** Uptime, current IP,
   watchdog and `cst` configured path cost are not rendered by this UI but are
   exposed publicly. References: `protocol.py:255-281` and
   `protocol.py:823-850`. These may be useful, but they are wire coverage rather
   than UI parity.
3. **D14: the 2,048 static-host limit is not UI-derived.** The UI table has no
   `W` maximum; the encoder rejects larger tables. References: `protocol.py:85`
   and `protocol.py:735-742`.
4. **D15: empty static-host MAC/VLAN values are UI validation holes.** Blank
   `adr` is omitted; `vid` declares min=1 but empty input bypasses the range
   check and serializes zero. Public models reject both at `models.py:614-647`.
   Device acceptance is unverified.
5. **D18: SFP blank/padding display differs from public normalization.** UI
   default-zero numeric controls blank `vcc`/`tbs` and preserve text whitespace;
   when any module text is present, public decoding reports zero and strips all
   SFP text. Reference: `protocol.py:988-1024`.
6. **D19: textual VLAN uniqueness can be bypassed.** UI duplicate detection
   compares current input strings, so `1` and `01` are distinct before both
   serialize as VID 1. Public table parsing/encoding rejects duplicate numeric
   VLAN IDs at `protocol.py:1458-1504`.
7. **D20: static-host duplicate keys are UI-accepted.** The UI has no unique
   constraint for MAC/VLAN pairs; public parsing and encoding reject duplicates
   at `protocol.py:703-731` and `protocol.py:743-770`.
8. **D21: arbitrary VLAN wire order is not exposed consistently.** UI Insert can
   place a row anywhere. Core retains internal `table_position`, but desired
   tuples must be VLAN-ID sorted and neither CLI nor Ansible exposes position.
   References: `models.py:836-852`, `protocol.py:1493-1529`, and
   `app.py:1921-1977`.

## Hardware status

This audit made only GET requests. It verified the exact UI artifact and every
ordinary UI data endpoint. `/sys.b`, `/link.b`, `/fwd.b`, `/rstp.b`,
`/!stats.b`, `/!dhost.b`, and `/snmp.b` were populated. `/sfp.b` represented an
empty module slot. `/vlan.b`, `/host.b`, `/!igmp.b`, and `/acl.b` returned empty
tables. Empty-table GET validation does not establish populated-row decoding or
any write behavior.

The repository contains opt-in destructive tests for representative write paths,
including password rotation, names, selected system masks, port flow control,
SNMP metadata, static hosts, RSTP, forwarding, ACL and VLAN. Those tests were
inspected but deliberately not run in this audit. Their presence is recorded as
“existing test,” never as fresh hardware validation and never as complete field
coverage.
